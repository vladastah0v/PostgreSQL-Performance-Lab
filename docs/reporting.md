# Сравнительные отчёты

Генератор собирает отчёт из сохранённых артефактов. Для формирования отчёта достаточно Python-окружения проекта, PostgreSQL, Redis и API можно оставить остановленными. В команду передаются конкретные каталоги прогонов. Это позволяет воспроизвести отчёт на том же наборе исходных измерений.

```bash
uv run --locked python -m scripts.generate_report \
  --sql-run benchmarks/results/sql-medium-2026-11-24 \
  --fastapi-run benchmarks/results/fastapi-medium-2026-11-24 \
  --redis-run benchmarks/results/redis-medium-2026-11-24 \
  --locust-run benchmarks/results/locust-medium-2026-11-24 \
  --index-file experiments/indexes/optimized-api.json \
  --output benchmarks/results/report-local
```

Для вывода одного формата укажите `--format json`, `csv`, `markdown` или `png`. По умолчанию создаётся весь комплект. Выходной каталог должен быть новым. Ссылки в отчёте указывают на исходные файлы относительно выходного каталога.

- `report.md` показывает сравнения, изменения, доступные счётчики ресурсов и ссылки на планы SQL.
- `report.json` содержит варианты, статусы, метрики, расчёты и ссылки на исходные данные. Неизвестный результат расчёта имеет значение `null`.
- `report.csv` содержит одну строку на метрику сравнения. Единица измерения указана в имени поля, например `p95_ms` или `error_rate_pct`. Для неизвестных значений используются пустые ячейки.
- Шесть PNG показывают SQL до и после, задержки FastAPI p50/p95/p99, RPS и ошибки Locust, режимы Redis и влияние индексов на чтение и запись. Matplotlib строит их в режиме Agg. [Документация Matplotlib](https://matplotlib.org/stable/users/explain/figure/backends.html)

## Как читать сравнения

Разность вычисляется как `до − после`, снижение задержки — как `(до − после) / до × 100%`, ускорение — как `до / после`. Отрицательное снижение означает рост задержки. При нулевом знаменателе соответствующий показатель остаётся пустым.

Основная метрика SQL и эксперимента записи — медиана времени выполнения. Для FastAPI и Redis используется HTTP p50, для Locust — медиана p95 отдельных повторов. RPS и доля ошибок Locust на графиках также показывают медиану и диапазон повторов. Сводка ресурсов Locust использует медианы доступных значений по прогонам. Режимы Redis сопоставляются с отключённым кэшем на том же наборе данных. Панели чтения и записи на графике индексов подписаны по своим экспериментам и ревизиям.

`COMPLETED` означает наличие обеих измеренных величин. `OBSERVED` отмечает отдельную серию HIT из профилирования FastAPI. `NOT_RUN` используется для отсутствующих экспериментов, `INCOMPLETE` для неполной пары, а `FAILED` для прогона с зарегистрированной ошибкой и без пары результатов. Раздел Locust хранит число неудачных прогонов вместе со статистикой завершившихся. Графики включают только доступные измеренные пары.
