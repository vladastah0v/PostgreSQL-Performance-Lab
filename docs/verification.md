## Повторный аудит от 25 ноября 2026 года

- Baseline проверяет единственный локальный `Host` с допустимым портом и отклоняет заголовки прокси. Запросы к API с недопустимым текстовым параметром отклоняются до обращения к PostgreSQL. В журнале Uvicorn остаются метод, путь и статус ответа, параметры строки запроса опускаются.
- Подключение к PostgreSQL ограничено `DB_CONNECT_TIMEOUT`, по умолчанию 5 секунд. При недоступности базы API возвращает 503. Redis использует до 64 соединений на воркер по умолчанию. Локальные бенчмарки FastAPI и Redis подключаются к API напрямую при заданных переменных HTTP-прокси.
- Docker Compose и CI используют сборку PostgreSQL 16 от 24 ноября с Debian-пакетами `libc6` 2.41-12+deb13u5, `libgssapi-krb5-2` 1.21.3-5+deb13u2 и `zlib1g` 1:1.3.dfsg+really1.3.1-1+deb13u1. Обновлены Prometheus до 3.16.0 и PostgreSQL Exporter до 0.21.1. Grafana 12.4.15 включает исправление CVE-2026-81843. [Образы PostgreSQL](https://github.com/docker-library/official-images/blob/master/library/postgres) · [Prometheus 3.16.0](https://github.com/prometheus/prometheus/releases/tag/v3.16.0) · [PostgreSQL Exporter 0.21.1](https://github.com/prometheus-community/postgres_exporter/releases/tag/v0.21.1) · [Бюллетень Grafana](https://grafana.com/security/security-advisories/cve-2026-81843/)

После перехода на `EVALSHA` сравнил образы API, собранные из `910a49c` и `1aa1e81`. Оба использовали одну PostgreSQL с набором `small` и один Redis. Три пары серий состояли из 60 последовательных запросов `HIT` к статистике клиентов. Порядок вариантов чередовался, HTTP-ответы совпали. Медиана прироста `total_net_input_bytes` снизилась с **67 465 до 49 585 байт** на серию, на **26,5%**. Результат относится к сетевому трафику Redis. Предварительную серию на 160 запросов прервала проверка условия `HIT`, поэтому для итоговых серий я прогревал каждую сторону прямо перед замером. [Команда Redis EVALSHA](https://redis.io/docs/latest/commands/evalsha/)

В Linux прошли **123 теста**, покрытие строк `app` составило **92,61%**. Прошли `alembic check` и Ruff. OSV через `uv audit --locked` не обнаружил известных уязвимостей в 78 Python-пакетах для Linux. В двух срабатываниях Bandit по SQL используются имена таблиц из констант генератора данных.

Docker Scout проверял образы `linux/amd64` с фильтром по высокой и критической тяжести и наличию исправления. Скан образов показывает совпадение версий пакетов с бюллетенями.

| Образ | Результат |
| --- | --- |
| API и Redis 7.4.12 | Найдено 0 срабатываний в выбранном фильтре. |
| PostgreSQL 16 | Число срабатываний в Debian-пакетах сократилось с 10 до 0. Оставшиеся 4 критических и 30 высоких относятся к Go 1.24.6 в бинарнике `gosu`, который запускает PostgreSQL от непривилегированного пользователя. Достижимость уязвимого кода из `gosu` отдельно не измерялась. |
| PostgreSQL Exporter | Обновление с 0.20.1 до 0.21.1 сократило результат с 5 критических и 26 высоких срабатываний до 0. |
| Prometheus | Обновление с 3.13.5 до 3.16.0 сократило результат с 4 высоких срабатываний до 2. Одно относится к `x/net` 0.61.0. Второе относится к псевдоверсии сборки Prometheus, хотя бюллетень указывает исправление начиная с 3.11.3. |
| Grafana | В базовом образе 12.4.15 скан показал 1 критическое и 7 высоких срабатываний. В сборке Compose `zlib` обновлён до 1.4-r0, `libssl3` и `libcrypto3` до 3.5.9-r1. Эти версии закрывают пять срабатываний по системным библиотекам. В репозитории Alpine v3.24 для x86_64 доступен `musl` 1.2.6-r3, а бюллетень сканера требует r6. Ещё два срабатывания относятся к Go-зависимости Tempo в бинарнике поставщика. |
